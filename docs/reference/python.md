<a id="assets"></a>

### Assets

```python
class Assets
```

The prices or returns of several assets over the same periods, with the settings that
turn them into annual figures.

`prices` is a pandas DataFrame indexed by date with one column of prices per asset, a
`finalytics.types.PriceTable`, or a CSV file (a `date` column and one column per
asset) given as a path or as text. Prices should include income, as adjusted closes do.
Dates on which an asset has no price are left out, with a warning, so that every asset's
returns cover the same periods.

- `risk_free_rate`: the annual risk-free rate, for Sharpe ratios; 0 by default.
- `risk_free_asset`: one of the assets, such as T-bills, to serve as the risk-free asset
  instead: its mean return is the risk-free rate, and optimisation leaves it out.
- `periods_per_year`: 252 for daily returns, 52 for weekly, 12 for monthly; detected from
  the dates by default.
- `covariance`: `"ledoit_wolf"` (the default), `"sample"`, `"oas"`, `"ewma"`
  (with a decay of 0.94), `"constant_correlation"`, `"denoised"` or
  `"nonlinear_shrinkage"`, or a `finalytics.types.CovarianceMethod` such as
  `Ewma(decay=0.97)` or `Statistical(factors=3)`.
- `mean_returns`: how expected returns are estimated: `"historical"` (the default),
  `"james_stein"` (shrunk towards the assets' average) or `"ewma"` (exponentially
  weighted, with a decay of 0.94), or a `finalytics.types.MeanMethod` such as
  `EwmaMean(decay=0.97)`.
- `classes`: each asset's class under classification schemes, such as
  `{"asset_class": {"US Equity": "Equity", "Bonds": "Fixed income"}}`, so that group limits
  can name a class: `groups={"Equity": ("asset_class", 0, 0.6)}`. A portfolio's assets
  carry its instruments' classes.


```python
import finalytics as fl

assets = fl.Assets(fl.datasets.asset_class_prices(), risk_free_asset="T-Bills")
result = assets.optimise(method="maximum_sharpe", max_weight=0.4)
result.results.weights
```

### Assets.optimise

```python
def optimise(self, *, method: _types.Method='maximum_sharpe', risk_free_rate: float | None=None, target: float | None=None, risk_aversion: float | None=None, uncertainty: _types.ReturnUncertainty | None=None, confidence: float | None=None, budgets: Mapping[str, float] | None=None, linkage: _types.Linkage | None=None, bounds: BoundLike | None=None, max_weight: float | None=None, asset_bounds: Mapping[str, BoundLike] | None=None, groups: Mapping[str, GroupLike] | None=None, min_effective_assets: float | None=None, expected_returns: Mapping[str, float] | None=None, resample: int | None=None, current_weights: Mapping[str, float] | None=None, max_turnover: float | None=None, min_trade: float | None=None, max_trades: int | None=None, benchmark_weights: Mapping[str, float] | None=None, max_tracking_error: float | None=None, cash: BoundLike | None=None, keep_cash: bool | Sequence[str]=False, frontier: bool=False, name: str | None=None) -> _types.Optimisation
```

The optimisation of the risky assets by `method`, fully invested in them unless `cash`
limits let it hold cash or `keep_cash` keeps the cash held: the weights in
`result.results.weights`, and the optimisation report in `result.report`, which
`print(result)` prints and `result.show()` shows. `name` titles the report. The
methods:

- `"maximum_sharpe"` (the default), `"minimum_variance"`,
  `"maximum_diversification"` and `"hierarchical_risk_parity"` (with `linkage`);
- `"mean_variance"` and `"robust_mean_variance"`, with `risk_aversion` (and
  `uncertainty`, an `finalytics.types.Ellipsoid` or a
  `finalytics.types.Box`);
- `"target_return"` and `"target_volatility"`, with an annual `target`;
- `"minimum_cvar"`, `"minimum_semivariance"` and `"minimum_cdar"`, measured on
  the periods' returns: the expected shortfall at `confidence` (0.95 by default), the
  mean square of the returns below zero, and the conditional drawdown at risk at
  `confidence` of the returns added up period by period; with `target`, each keeps an
  annual expected return of at least `target`;
- `"risk_parity"`, every asset with the same share of the risk, and
  `"risk_budgeting"`, with shares given by `budgets` by asset;
- `"equal_weight"` and `"inverse_volatility"`, the baselines estimated portfolios
  must beat.

`max_weight` is the largest weight of any asset, such as 0.4; `bounds` limits every
weight, `(0, 1)` by default; `asset_bounds` limits particular assets, such as
`{"Gold": (0, 0.1)}`; `groups` limits the total weight of groups of assets, such as
`{"Equity": (["US Equity", "Intl Equity"], 0.3, 0.6)}`, or the assets of a class,
`{"Equity": ("asset_class", 0.3, 0.6)}` (see `classes`); `min_effective_assets`, such
as 5, spreads the weights over at least as many assets as 5 equal weights would be,
holding `1 / sum(w ** 2)` at or above it. Equal weight, inverse volatility, risk
parity, risk budgeting and hierarchical risk parity are fully invested and long only,
and take no limits. Expected returns are the assets' estimates (see `mean_returns`)
unless `expected_returns` gives others.

`resample=200` averages the optimal weights for 200 histories simulated from the
estimates, each as long as the assets' returns (Michaud's resampling), which makes the
weights less sensitive to errors in the estimates; `result.results.resampled` says how
much each weight varied. It applies to the methods that use estimates, other than those
measured on the periods' returns.

`current_weights` are the weights held now, by asset, adding up to one with the cash,
such as `{"US Equity": 0.5, "Bonds": 0.45, "T-Bills": 0.05}` or a portfolio's own
`portfolio.weights()`: the report lists the trades from them, and they are where the
trade limits start. Like every input of weights, they may name any of the assets, the
risk-free asset and cash in other currencies included, or `"Cash"` at the risk-free
rate where there is no risk-free asset; optimisation invests the cash it does not
choose.
`max_turnover` limits the one-way turnover from them, `sum(abs(w - current)) / 2`
with the cash, such as 0.2; `min_trade` makes each trade at least that weight or none,
and `max_trades` limits how many assets are traded (both met by leaving trades out one
by one, so not for the methods measured on the periods' returns).
`benchmark_weights` gives the report the tracking error against a benchmark, and
`max_tracking_error` limits it, a year, such as 0.03.

`cash=(0, 0.2)` lets the weights hold between none and 20% in cash, riskless: in the
risk-free asset, earning its return, or, without one, in `"Cash"` at the risk-free
rate. The frontier then includes the cash. Without it, the weights are fully invested
in the risky assets. The Sharpe and diversification methods take no limits on cash.

`keep_cash=True` keeps every currency's cash held now at its current weight, and
`keep_cash=["USD"]` that of the currencies named, as `Portfolio.rebalance` keeps
it: the rest is optimised, and the limits are measured on the whole portfolio, so that
`portfolio.rebalance(result, keep_cash=True)` trades what they allow. The weights hold
the kept cash at its weight. It needs `current_weights`, and the cash it keeps takes no
`cash` limits.

`frontier=True` draws the efficient frontier under the same limits in the report. It
takes 30 more optimisations, so it adds time that grows with the number of assets, to
seconds for hundreds of assets; without it, the report shows the weights against each
asset and equal weight.

```python
def evaluate(self, weights: Mapping[str, float], *, risk_free_rate: float | None=None, expected_returns: Mapping[str, float] | None=None, frontier: bool=False, bounds: BoundLike | None=None, max_weight: float | None=None, asset_bounds: Mapping[str, BoundLike] | None=None, groups: Mapping[str, GroupLike] | None=None, min_effective_assets: float | None=None, cash: BoundLike | None=None, name: str | None=None) -> _types.GivenWeights
```

`weights` by asset valued on the estimates `optimise` uses: the figures in
`result.results` (expected return, volatility, Sharpe ratio and each asset's share of

assets' own, as for `optimise`. `frontier=True` draws the efficient frontier in
the report under the limits given (`bounds`, `max_weight`, `asset_bounds`, `groups`,
`min_effective_assets` and `cash`, as for `optimise`), which apply to nothing
else.

```python
def frontier(self, *, points: int=20, bounds: BoundLike | None=None, max_weight: float | None=None, asset_bounds: Mapping[str, BoundLike] | None=None, groups: Mapping[str, GroupLike] | None=None, min_effective_assets: float | None=None, expected_returns: Mapping[str, float] | None=None, current_weights: Mapping[str, float] | None=None, max_turnover: float | None=None, min_trade: float | None=None, max_trades: int | None=None, benchmark_weights: Mapping[str, float] | None=None, max_tracking_error: float | None=None, cash: BoundLike | None=None, keep_cash: bool | Sequence[str]=False, risk_free_rate: float | None=None) -> list[_types.FrontierPortfolio]
```

The efficient frontier: `points` portfolios of the risky assets, from the one with
the least variance to the one with the largest expected return, under the limits given
as for `optimise`, trade and tracking-error limits and cash included. It takes no

`"Cash"`, for assets without a risk-free asset whose frontier holds cash, and
`keep_cash` holds the cash of `current_weights` at its weight on every portfolio.

### Assets.compare

```python
def compare(self, *, methods: Sequence[_types.Method | tuple[str, Mapping[str, float]] | _types.FixedWeights]=(), weights: Mapping[str, Mapping[str, float]] | None=None, name: str | None=None, validation: _types.Validation | str='in_sample', rebalance: _types.RebalanceSchedule | str='quarterly', trading_cost_bps: float=0.0, benchmark: Any=None, benchmark_name: str | None=None, max_weight: float | None=None, bounds: BoundLike | None=None, asset_bounds: Mapping[str, BoundLike] | None=None, groups: Mapping[str, GroupLike] | None=None, min_effective_assets: float | None=None, target: float | None=None, risk_aversion: float | None=None, uncertainty: _types.ReturnUncertainty | None=None, confidence: float | None=None, budgets: Mapping[str, float] | None=None, linkage: _types.Linkage | None=None, expected_returns: Mapping[str, float] | None=None, risk_free_rate: float | None=None, resample: int | None=None, max_turnover: float | None=None, min_trade: float | None=None, max_trades: int | None=None, benchmark_weights: Mapping[str, float] | None=None, max_tracking_error: float | None=None, cash: BoundLike | None=None, keep_cash: bool | Sequence[str]=False, start_value: float | None=None, flows: FlowsLike=()) -> _types.Comparison
```

The comparison of `methods`, each backtested on these assets with the same limits,
rebalancing, validation and trading costs and scored on the periods it was tested on:
the comparison report in `result.report`, and every return and trade in
`result.results`. `print(result)` prints the report and `result.show()` shows it,
inline in a notebook or in a browser. `name` titles the report. The results and the
report keep the strategies in the order given.

`weights` adds fixed weights by name, such as `{"60/40": {"US Equity": 0.6, "Bonds":
0.4}}`, after the methods, held and rebalanced as the methods are and scored on the same
periods; they are not fitted to any returns, so they have no run in sample. Fixed
weights may also come among the methods, as a name and weights: `methods=[("60/40",
{...}), "minimum_variance"]`.

- `validation`: `"in_sample"` (the default); `finalytics.Holdout`, such as
  `fl.Holdout(start="2016-11-01")`, which fits on the history before the date and
  tests on the rest; or `finalytics.WalkForward`, such as
  `fl.WalkForward(years=5)`, which refits at each scheduled rebalance on the last
  five years (or all the history so far, with `expanding=True`).
- `rebalance`: `"monthly"`, `"quarterly"` (the default), `"yearly"`,
  `"never"`, `finalytics.Drift`, such as `fl.Drift(band=0.05)`, or
  `finalytics.Every`, such as `fl.Every(periods=21)` for about once a month
  with daily returns.
- `trading_cost_bps`: the cost of trading in basis points of the value traded.
- `benchmark`: weights by asset, such as `{"US Equity": 0.6, "Bonds": 0.4}`, or an
  index's prices, as a pandas DataFrame indexed by date with one column;
  `benchmark_name` names it (`"Benchmark"` by default, or the prices' column name).
- `start_value` and `flows`: money to follow as well as returns. Each run starts with
  `start_value`, and `flows` pays in (positive) or takes out (negative) amounts on
  dates, such as `{"2020-01-31": 500}`, at the end of the period each falls in; the
  reports then give each run's ending value and money-weighted return.

The limits and parameters are those of `optimise`; they apply to every method
that takes them. `max_turnover`, `min_trade` and `max_trades` limit the trades at each
refit of a walk-forward validation, from the weights held then (the first fit enters
from cash), and `keep_cash` keeps the cash held at each refit; `max_tracking_error`
applies at every fit.

### Assets.plan

```python
def plan(self, goal: _types.Goal | _types.PlanOptions | None=None, *, weights: MixLike | None=None, inflation: float | Any=None, flows: Sequence[_types.PlanFlow]=(), start_value: float=0.0, alternatives: Mapping[str, MixLike] | Sequence[MixLike]=(), fee: float=0.0, chance: float | tuple[float, float]=0.8, model: _types.Model | str='bootstrap', expected_returns: Mapping[str, float] | None=None, start: str | datetime.date | None=None, end: str | datetime.date | None=None, simulations: int=10000, seed: int=0, currency: str | None=None, name: str | None=None) -> _types.Plan
```

The chance that a plan of saving, spending and investing meets one `goal`, from
`simulations` markets drawn from these assets' monthly returns: the planning report in
`plan.report`, and the raw results in `plan.results`. `print(plan)` prints the
report and `plan.show()` shows it, inline in a notebook or in a browser.

- `goal`: `finalytics.Target`, an amount by a month, such as
  `fl.Target(amount=150_000, by="2030-06")`; `finalytics.Payments`, an
  amount paid regularly, such as `fl.Payments(amount=4_000, start="2046-11",
  end="2076-10")`; or none, for a projection to the month `end`.
- `weights`: what the money is invested in, rebalanced every month: weights by asset,
  such as `{"US Equity": 0.6, "Bonds": 0.4}`; a name and weights, such as
  `("Balanced 60/40", {...})`; a `finalytics.GlidePath`; or a result with
  weights, such as a frontier portfolio.
- `inflation`: the rate a year, such as `0.025`, or a price index of one column, such
  as a consumer price index, as a pandas DataFrame indexed by date. Every amount is in
  today's money: returns are after inflation and fees.
- `flows`: money paid in and taken out, such as `fl.Saving(amount=1_500,
  every="month")`, which runs until the goal, or `fl.Spending(name="Car",
  amount=25_000, on="2028-03")`.
- `alternatives`: other mixes to compare on the same simulations, by name.
- `chance`: the chance wanted (0.8 by default), or the chance wanted and the chance from
  which the plan has room to spare, such as `(0.85, 0.95)`.
- `model`: `"bootstrap"` (blocks of past months, the default), `"normal"` or
  `"historical"`, or `finalytics.Bootstrap` with its `block` length.
- `start`: the first month, the month after the assets' last by default.

A goal kept with a portfolio (`Portfolio.goals`), a whole plan with its settings,
is planned as it is: `assets.plan(portfolio.goals[0])`, with no other arguments.

### MarketData

```python
class MarketData
```

Prices and FX rates for valuing a portfolio.

Prices are in each instrument's currency; an FX rate is the number of units of `quote` per
unit of `base`. A rate can be found directly, inverted, or crossed through the pivot
currency. A missing value may be carried forward from an earlier date for at most
`max_carry_days` days, and carried values are reported as warnings.

Each method that adds data returns a new `MarketData`.

### Portfolio

```python
class Portfolio
```

A portfolio: its records (base currency, accounts, instruments and transactions), the

Read one from CSV files with `from_csv` (only the transactions are required), from a

`MarketData`. A portfolio does not change: `with_transactions` and
`with_rebalance` return new ones.

<a id="portfolio-from-csv"></a>

### Portfolio.from_csv

```python
def from_csv(cls, *, transactions: TextOrPath, prices: TextOrPath | None=None, fx: TextOrPath | None=None, instruments: TextOrPath | None=None, accounts: TextOrPath | None=None, goals: TextOrPath | None=None, base_currency: str | None=None, delimiter: str=',') -> Portfolio
```

A portfolio from CSV files, each given as a path or as text.

- `transactions`: one row per transaction, with a `date` (or `trade_date`), a
  `type` and the columns the type needs, such as `instrument`, `quantity` and
  `price` for a `buy`, or `amount` and `currency` for a `deposit`. Rows may
  give an `id` (`t1`, `t2` and so on by default) and an `account` (`main`).
- `prices`: a `date` column and one column per instrument, or `date`,
  `instrument` and `price` columns.
- `fx`: a `date` column and one column per pair, such as `EUR/USD`, for instruments
  and cash in other currencies.
- `instruments`: `id`, `kind` and `currency`, with `class.<scheme>` columns such
  as `class.asset_class` for grouping. Without it, each instrument is in the currency
  given with it in the transactions, or else in the base currency.
- `accounts`: `id`, with `name`, `lot_method` and `class.<scheme>` columns.
  Without it, each account the transactions name is created.
- `goals`: goals kept with the portfolio, one record per row: `goal` (its name) and
  `type`, a `target`, `payments` or `projection` row with the plan's settings,
  and `saving`, `spending`, `mix`, `alternative`, `glide` and
  `alternative_glide` rows; `goals` gives them, for `Assets.plan`.
- `base_currency`: the currency results are reported in; by default, that of the first
  deposit.

`fl.datasets.file("portfolio/transactions.csv")` and the other dataset files show each
layout, and the data guide (https://github.com/sigmafieldlabs/finalytics/blob/main/docs/data.md) describes every column. Every problem in every
file is reported at once, by line and column, in a `finalytics.ValidationError`.

<a id="portfolio-rebalance"></a>

### Portfolio.rebalance

```python
def rebalance(self, targets: Mapping[_types.HoldingKey, float] | _types.Optimisation | _types.OptimisationResult, *, accounts: Sequence[str] | None=None, as_of: DateLike | None=None, lot_method: _types.LotMethod | None=None, whole_units: bool=False, minimum_trade: float=0, fee_bps: float=0, fee_per_trade: float=0, minimum_fee: float=0, tax: tuple[float, float] | None=None, long_term_after_days: int | None=None, keep_cash: bool | Sequence[str]=False, name: str | None=None) -> _types.Rebalancing
```

The trades that move `accounts` (by default every account) together to `targets`:
weights by holding (an instrument's identifier, or `"USD cash"` and the like), as
shares of their combined value on `as_of` (by default the last price date), or an
optimisation of the portfolio's assets, whose weights are its targets (one that found
no weights is a `ValidationError`). The rebalance report is in
`result.report`, which `print(result)` prints and `result.show()` shows, and each
account's proposal in `result.results`; `with_rebalance` makes the trades.
`name` titles the report.

Instruments held but not listed are sold; base-currency cash takes the weight the
targets leave, and other currencies are converted to their targets (zero if not
listed). A holding above its target is sold from the accounts that hold it in
proportion to their holdings, and one below is bought in proportion to the value each
account has free; trades do not move cash between accounts. Sales take lots by
`lot_method`, by default each account's own. Trades worth less than `minimum_trade` in
the base currency are left out.

Each trade pays a fee of `fee_bps` basis points of its value plus `fee_per_trade`, and
at least `minimum_fee`, in the instrument's currency; purchases leave room for the fees.
With `tax`, the rates on short-term and long-term gains such as `(0.37, 0.20)`, sales
in taxable accounts take the lots that cost the least tax, and the tax is estimated; a
gain is long-term after `long_term_after_days` (365 by default), and an account that is
not taxable, such as a retirement account, pays none.

`keep_cash=True` keeps every currency's cash as it is, and `keep_cash=["USD"]` that
of the currencies named: the other targets then share the rest of the value, so the
trades neither invest that cash nor add to it. Targets that leave the kept cash out are
shares of the rest; targets that give it its weight now, as an optimisation with the same
`keep_cash` gives them, are shares of the whole value and are traded as they are. By
default the targets are shares of the whole value, cash included.

<a id="portfolio-shock-scenario"></a>

### Portfolio.shock_scenario

```python
def shock_scenario(self, *, instruments: Mapping[str, float] | None=None, groups: Mapping[tuple[str, str], float] | None=None, currencies: Mapping[str, float] | None=None, factors: Mapping[str, float] | None=None, factor_model: _types.FactorModel | _types.FactorModelEstimate | None=None, propagate: bool=False, date: DateLike | None=None, group_by: Sequence[str]=(), risk: _types.Matrix | _types.FactorModel | _types.FactorModelEstimate | None=None, confidence: float=0.95, stress: _types.CorrelationStress | None=None) -> _types.ScenarioResult
```

What shocks would do to the holdings on `date` (by default the last price date).

`instruments` and `currencies` map identifiers and currency codes to returns, and
`groups` maps `(scheme, value)` pairs, such as `("asset_class", "Equity")`, to the return
of every instrument in the group. `factors` maps factor names of `factor_model` to
returns; with `propagate`, the other factors move by their expected return given them.
An instrument's own shock comes first, then the one group that matches it (more than one
is an error), then the factors; an instrument none of them reaches is listed as not
shocked. Currency shocks compound with an instrument's return and move cash.

With `risk` (a covariance matrix or factor model of the holdings' returns, labelled by
instrument and "EUR cash" style labels), the result has the risk before and after, the
latter with the covariance stressed by `stress`.

<a id="portfolio-historical-scenario"></a>

### Portfolio.historical_scenario

```python
def historical_scenario(self, start: DateLike, end: DateLike, *, proxies: Mapping[str, str] | None=None, date: DateLike | None=None, group_by: Sequence[str]=(), risk: _types.Matrix | _types.FactorModel | _types.FactorModelEstimate | None=None, confidence: float=0.95, stress: _types.CorrelationStress | None=None) -> _types.ScenarioResult
```

What the price and exchange-rate changes from `start` to `end` would do to the
holdings on `date` (by default the last price date), with the holdings' value on each
date in between. `proxies` maps instruments with no prices then to instruments whose
prices stand in for them; their own currency's rate still applies. `group_by`, `risk`,
`confidence` and `stress` are as for `shock_scenario`.

  `volume` and `dividends` if known, one row per security and date, in any order;
- a mapping of each security to a pandas Series of closes indexed by date, or to a DataFrame
  of `close`, `volume` and `dividends` columns;
- a CSV file, given as a path or as text: the long layout, or a `date` column and one
  column of closes per security, empty where a security has none.

A close that is not a number is no close, and its date is left out with a warning.

- `fields`: values the library does not compute, such as a sector or a price-to-earnings
  ratio, for rules and results: a DataFrame indexed by security with one column per field,
  a mapping such as `{"AAPL": {"sector": "Technology", "pe_ratio": 31.2}}`, or a CSV file
  or text with an `id` column.
- `benchmark`: one of the securities, such as an index, for beta, correlation and relative
  returns.
- `risk_free_rate`: the annual rate of the Sharpe and Sortino ratios; 0 by default.

```python
import finalytics as fl

universe = fl.Universe("prices.csv", fields="instruments.csv", benchmark="BENCH")
screen = universe.screen(rules=[("return_1y", ">", 0)], sort=("sharpe_ratio", "descending"))
screen.show()
```

<a id="universe-screen"></a>

### Universe.screen

```python
def screen(self, *, as_of: _arrays.DateLike | None=None, max_carry_days: int=5, measures: Sequence[_types.Measure] | None=None, rules: Sequence[RuleLike]=(), sort: SortLike | None=None, limit: int | None=None, formulas: Mapping[str, str] | None=None, include_benchmark: bool=False, name: str | None=None) -> _types.Screen
```

Screens the universe: each security measured on its own closes up to `as_of`, judged
on the `rules`, with the matches sorted and limited. The raw results are in
`screen.results`, one row per security, and the screening report in
`screen.report`, which `print(screen)` prints and `screen.show()` shows; `name`
titles it. `finalytics.pandas.securities` turns the results into a DataFrame.

- `as_of`: the date measured to; the latest date in the universe by default. A security
  whose last close is more than `max_carry_days` (5) earlier is stale: listed, but not
  measured.
- `measures`: the measures to compute, such as `["return_1y", "rsi_14"]`; every one
  the universe allows by default. Those the rules and the sort use are computed too.
- `rules`: all of which a match meets, each `(name, op, value)`: a measure or numeric
  field compared with `"<"`, `"<="`, `">"` or `">="` a number, or
  `"between"` a `(low, high)` pair; or a text field `"in"` or `"not_in"` a list
  of values. A security without the value a rule tests fails it.
- `sort`: `(name, order)`, a measure or numeric field and `"descending"` or
  `"ascending"`; `limit`: the most matches to keep.
- `formulas`: numeric fields computed for each security, by name, in order, such as
  `{"risk_adjusted": "return_1y / volatility"}`, which the rules, the sort and the
  results then take by name. A formula is numbers, the names of measures, numeric
  fields and earlier formulas, `+ - * /`, parentheses, and `abs`, `sqrt`, `log`,
  `min` and `max`; a security has no value where an input has none or the formula
  has no finite result, such as on division by zero.
- `include_benchmark`: screen the universe's benchmark as a candidate too. By default it
  serves beta and the other measures against it, and is not listed.

Every problem is reported together, in one `finalytics.ValidationError`.

## finalytics.opt

Portfolio optimisation: objectives, constraints, the efficient frontier and rebalancing.


```python
import finalytics as fl

labels = ["stocks", "bonds", "gold"]
cov = [[0.04, 0.006, 0.0], [0.006, 0.01, 0.001], [0.0, 0.001, 0.02]]
mu = [0.08, 0.04, 0.06]
problem = fl.opt.Problem.from_covariance(cov, labels=labels, expected_returns=mu)

```

Black–Litterman expected returns blend the returns implied by market weights with views:

```python
import finalytics as fl

labels = ["stocks", "bonds", "gold"]
cov = [[0.04, 0.006, 0.0], [0.006, 0.01, 0.001], [0.0, 0.001, 0.02]]
estimate = fl.opt.black_litterman(
    cov,
    [fl.opt.View(portfolio={"bonds": 1.0}, expected_return=0.05)],
    market_weights=[0.6, 0.3, 0.1],
    risk_aversion=2.5,
    labels=labels,
)
solution = fl.opt.Problem.from_black_litterman(estimate).solve(fl.opt.MeanVariance(risk_aversion=2.5))
```

## finalytics.printing

The reports and results as text and as an HTML page.

The report and result classes in `finalytics.types` derive from these, so that
`print(report)` shows a report as text, 80 columns wide, and a report can be saved as one HTML
page or shown, inline in a notebook or in a browser, or by a handler set with
`set_show_handler`. The results of `Assets.optimise`, `Assets.compare` and
`Assets.backtest` print and show their report, and their raw results print as text too.

<a id="set-show-handler"></a>

### set_show_handler

```python
def set_show_handler(handler: Callable[[str], object] | None) -> None
```

Sets what `show()` does with a report's page: from then on, `show()` calls `handler`
with the page's HTML instead of showing it in a notebook or a browser, and returns `None`.
`None` restores the default.

For programs that show pages themselves: a web page running Python in Pyodide, which has no
browser to open, or an app that puts the page in a view of its own:

```python
import finalytics as fl

pages = []
fl.set_show_handler(pages.append)
fl.Assets(fl.datasets.asset_class_prices()).optimise(method="minimum_variance").show()
assert pages[0].startswith("<!doctype html>")
fl.set_show_handler(None)
```
